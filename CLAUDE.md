# CLAUDE.md — Omni Video Skill & omni-video-agent MCP Agent

Guidance for Claude Code when working in this repository.

## Project Overview

This repository packages one Claude Code skill (`omni-video`) and one **Model Context Protocol (MCP) server** (`omni-video-agent`, a FastMCP app in `server.py`). Together they:

1. **Generate videos:** text-to-video with `gemini-omni-flash-preview` (Omni Flash) via the stateful Interactions API, with configurable aspect ratio and delivery mode.
2. **Edit iteratively:** multi-turn stateful edits chained by interaction ID (`edit_video`), plus image-driven generation (animate a still, interpolate keyframes, subject references), local-video restyling via the Gemini File API, and YouTube publishing.

The tool surface is exactly eight tools: `generate_video`, `edit_video`, `animate_image`, `interpolate_images`, `generate_with_subjects`, `edit_user_video`, `upload_to_youtube`, `get_help`. Public repo: [github.com/xbill9/omni-skill-claude](https://github.com/xbill9/omni-skill-claude), Apache-2.0 (`LICENSE` — keep it in sync with the license declared in `.claude-plugin/plugin.json`).

## Repository Layout & the Snapshot Sync Model

The repo-root files are authoritative; the skill is distributed as generated copies. **Edit the sources, then run `make skill` — never edit a snapshot directly.**

- **Sources (root):** `SKILL.md` (the skill manifest), `server.py` (the MCP server), `requirements.txt`, `mcp/project-setup.sh` (installer), `references/gemini-interactions-api.md` (the video Interactions API guide bundled with the skill — hand-maintained; keep it consistent with `GEMINI.md` and the server).
- **Helper scripts (root):** `init.sh` — local bootstrap (deps + `.mcp.json` entry pointing at the root `server.py` + key setup; safe to rerun). `project-setup.sh` — thin wrapper that refreshes the `mcp/` snapshot then delegates to `mcp/project-setup.sh` (the real installer). `set_env.sh` — reads/prompts for the key (`~/gemini.key`), writes `.env`, and injects the key into `.mcp.json`; caution: it **replaces** the entry's whole `env` block with just the two key vars, dropping any custom `GEMINI_OMNI_MODEL`. `refresh_skill.py` — the snapshot sync run by `make skill`.
- **Generated by `make skill` (`refresh_skill.py`):**
  - `mcp/{server.py,requirements.txt}` — snapshots of the root sources (root copy is authoritative if they differ)
  - `.claude/skills/omni-video/` — the assembled skill (active when working in this repo)
  - `skills/omni-video/` — full copy of the skill in plugin layout (for the marketplace)
- **Generated, gitignored:** `.mcp.json` and `.env` (both embed the Gemini API key) — created by `./init.sh` on first run; `set_env.sh` injects the key. `client_secrets.json` and `token.pickle` (YouTube OAuth credentials, created next to the server on first `upload_to_youtube` run) are gitignored too. Never commit any of them or hand-edit them back into git. The key itself persists in `~/gemini.key`.
- **Plugin marketplace:** `.claude-plugin/plugin.json` + `.claude-plugin/marketplace.json` make the repo installable via `/plugin marketplace add xbill9/omni-skill-claude`. The plugin auto-registers the `omni-video-agent` server (no key in the manifest — the server reads `GEMINI_API_KEY` from the environment). Validate changes with `claude plugin validate .`
- **Distribution zip:** `dist/omni-video-skill.zip`, built by `make skill-package`; committed so the raw-GitHub-URL install works — rebuild it when the skill changes.

## Common Commands

```bash
./init.sh          # Local bootstrap: deps + .mcp.json (root server.py) + API key
make skill         # Refresh all skill snapshots + plugin copy from the root sources
make skill-install # Refresh + copy the skill to ~/.claude/skills (all projects)
make skill-package # Refresh + rebuild dist/omni-video-skill.zip
make init TARGET=/path/to/project ARGS='--model <name>'  # install skill + register MCP server
make test          # Agent unit tests (test_agent.py; API mocked, no key needed)
make lint          # ruff check + format --check on the Python sources, bash -n on the scripts
claude plugin validate .   # check .claude-plugin manifests
```

The server's config comes from env vars: `GEMINI_API_KEY` (or `GOOGLE_API_KEY` fallback) and `GEMINI_OMNI_MODEL` (default `gemini-omni-flash-preview`). The Gemini client is constructed at import time, so the key must be present **before the server starts** — a missing key is a startup failure, not a tool error. Videos are saved to the server's working directory (there is no output-dir env var).

## Technical Standards: Omni Flash & the Interactions API

The Interactions API is Gemini's **stateful** endpoint: each call returns an `interaction_id` representing the turn's visual context persisted server-side, and passing `previous_interaction_id` lets the model edit the existing video while preserving scene, character, lighting, and style continuity — no re-prompting the full scene. Full guide: `references/gemini-interactions-api.md` (and `GEMINI.md`).

### Request — `client.interactions.create(...)` (google-genai SDK)

| Parameter | Type | Notes |
| :--- | :--- | :--- |
| `model` | `str` | `"gemini-omni-flash-preview"` (the server reads `GEMINI_OMNI_MODEL`). |
| `input` | `str` \| `list` | Text prompt, or a list mixing `{"type": "image", "data": <b64>, "mime_type": ...}`, `{"type": "document", "uri": <file-api-uri>}` (an uploaded video), and `{"type": "text", "text": ...}` parts. |
| `response_format` | `dict` | `{"type": "video"}`; optional `"aspect_ratio"`: `16:9` or `9:16` (generation only — stateful edits inherit it); optional `"delivery": "uri"` for File API delivery of large outputs. |
| `previous_interaction_id` | `str` | Chain from the **latest** turn's ID — a stale ID silently forks the session from an older state. |
| `store` | `bool` | Must be `True` for any turn you may edit later; the MCP tools always set it. |
| `background` | `bool` | The server passes `False` — calls block until the video is ready. |

### Response — as consumed by `_handle_response` in `server.py`

- `interaction.id` — the new interaction ID to chain into the next edit (every turn returns a **new** one).
- `interaction.output_video` — may be absent (report the ID and the no-video note, don't crash). Inline delivery: base64 in `.data`. URI delivery: `.uri` points at the Google File API — poll `client.files.get(...)` until `ACTIVE` (up to 300s, fail on `FAILED`), then `client.files.download(...)`.
- Saved as `<prefix>_<unix-ts>.mp4` (`gen_`/`edit_`/`animated_`/`interpolation_`/`subject_`/`user_edit_`) in the server's working directory.

### Practices

- **Keep edit prompts incremental** — describe only the change ("make it nighttime with rain"); the stored context holds the rest.
- **Pick the aspect ratio at generation time** — stateful edits inherit it; only `generate_video` accepts one.
- **Prefer `delivery='uri'` for large outputs** — inline base64 can fail past ~4 MB.
- **Tool errors return as `🔴 ...` text strings** (the YouTube tool uses `❌ ...`), not protocol errors — check for them before reporting success.
- **`upload_to_youtube` needs one-time OAuth**: `client_secrets.json` (OAuth Desktop App) in the server's working directory; the first run opens a browser and caches `token.pickle`. Its extra deps (`google-api-python-client`, `google-auth-oauthlib`, `google-auth-httplib2`) are optional — the tool reports the pip command when missing.
- **Generations block and are billable** — batch related edits into one well-specified prompt when cost or latency matters.
- **Universal help:** the agent exposes a standardized `get_help` tool describing all exposed tools, delivery modes, and prompting best practices.

Upstream docs: [Interactions API Reference](https://ai.google.dev/api/interactions-api), [raw API details](https://ai.google.dev/api/interactions.md.txt).

## Coding Standards

- **No virtualenvs:** use the system `python3`; if dependencies are missing, warn with the `pip install -r requirements.txt` command instead of creating a venv (this is also how `mcp/project-setup.sh` behaves).
- **Dependency portability:** do not assume third-party libraries like `pandas` are installed. Prefer the standard library for data parsing and aggregation scripts.
- **Never commit secrets:** `.env`, `.mcp.json`, `~/gemini.key`, `client_secrets.json`, and `token.pickle` carry credentials and stay out of git.
